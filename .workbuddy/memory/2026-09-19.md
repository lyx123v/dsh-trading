# 2026-09-19

## 交付：中栏 TradingView 图表左缘惰性历史分页

用户诉求：图表不能左右滚动加载更多历史，要支持加载所有历史。根因不是纯前端交互，而是取数接口层缺「往更早翻页」能力（`MarketDataService.getKlines` 只有 `limit`）+ 客户端固定条数（日线 750 / crypto 300 / 其他 500）。

### 落地范围

- **契约**（`packages/api/src/index.ts`）：`KlineQuery{before?}` 追加为 `getKlines` 可选第 4 参；新增可选 `getKlineHistoryCapability?()`。`before` = 取 `openTime` **严格早于** 该 epoch ms 的 K 线。
- **桥**（`bridge.ts`）：`/klines?before=`；**能力闸 fail-closed** —— 未声明支持时抛 `TRADING_KLINE_HISTORY_UNSUPPORTED` 且**不调用上游**；响应恒带 `history{supportsEarlier,provider?,maxPageSize?}`。
- **客户端**：新增 `kline-history.ts`（状态机 + 常量唯一家）、`chart-viewport.ts`（视窗数学）、`useKlineHistory.ts`（时序与竞态）；`TvChart.tsx` 接入三分支 `detectHeadChange`（reset/append/prepend）+ 视窗补偿。
- **四源真分页**（均经真实网络取证）：binance `endTime=before−1`(ms,闭区间) 全周期 1000；okx `after=before`(零换算) 全周期 300；tencent `end=before 日−1`(YYYY-MM-DD,start 留空) 仅日/周/月 800；eastmoney `end=before 日−1`(YYYYMMDD) 仅日/周/月、**刻意不声明 maxPageSize**。
- **yahoo 排除**：自 2021-11-01 起对中国大陆整体关闭，返回区域通知页而非 JSON，无法取证 → us 维持降级；证据与「本机补证命令」在 `spikes/impl-tv-history-paging/NET-VERIFY.md`。

### 被验证证伪的两个真缺陷（都已修）

1. **resync × 前插竞态 → 状态机永久卡 `loading`**。旧实现用「key+游标」单槽 token，resync 会覆写它，使在途前插响应被静默丢弃且**不释放 inflight**。改为**世代守卫**（单调 `generationRef`+`keyRef`，仅换 dataKey 才作废）+ resync 单飞闸 + 统一释放点。
2. **分钟周期误导性 error**。capability 是 provider 级单布尔，tencent/eastmoney 分钟线实际不支持（抛 `TRADING_NOT_IMPLEMENTED`），客户端却报「加载失败」而非「不支持更早历史」。修法：`TRADING_NOT_IMPLEMENTED` 与 `TRADING_KLINE_HISTORY_UNSUPPORTED` 归入同一终态 `unsupported`。

### 重要教训

- **`pnpm -r build` 绿 ≠ 类型正确**：esbuild 不做类型检查。真门禁是 `node scripts/typecheck-gate.mjs --check`。
- **契约「追加可选第 4 参 = 既有实现方零改动」不成立**：`connector-ccxt` 第 4 参早已被 `exchange` 占用，必须顺延第 5 参。凡追加位置参数前先 grep 全部实现方的形参表。
- **并发构建会污染门禁读数**：曾在 `pnpm -r build` 并行时读出门禁 481（+6，含 strategies +4），串行复跑实为 477（+2，仅 ccxt）。读门禁数字前先确认没有并行构建。
- **证明测试有效性要靠「回退验证」**：把守卫改回旧逻辑，确认用例真的失败，再恢复。否则测试可能只是陪跑。

### 环境坑（本机 Windows）

- 本会话 Bash 工具缺 `ls`/`cat`/`sed`/`head`/`tail`/`find`/`rm`/`dirname`/`uname`，只有 `node`/`git`/`echo` 可用；`pnpm` 是 shell 包装脚本，**在 Bash 里必崩**（`Cannot find module ...pnpm.cjs`）。跑 pnpm 要用 PowerShell。
- PowerShell 工具 stdout 回显失效，但命令确实执行；**需重定向到文件再用 Read 读**。
- `pnpm -r test` **遇首个失败即中止**（`ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`），会连带使后续链路不执行。`packages/base` 的 symlink 用例在 Windows 无符号链接权限时必失败 —— 属环境性，非改动引入。
- `scripts/refresh-trading-web-profile.sh` 是 **macOS 专用**（硬编码 `/opt/homebrew/...`），且 profile 里的 `@dshtrading/*` 是**真实目录副本而非软链** —— 改完源码必须刷新 profile 副本，UI 才会看到新代码；否则会拿旧快照验证得出假通过。校验方法：该副本 `lib/client.js` 是否含新标识符（如 `useKlineHistory`）。
